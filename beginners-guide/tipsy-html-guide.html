What this actually is

Description and Opening aren't locked to plain text. Tipsy renders real HTML and CSS in these two fields — actual styling, not just line breaks and bold text.

Keep expectations calibrated: it's markup rendered inside a card component on the platform, not a JavaScript sandbox and not an embedded webpage. Think "a styled document," not "a website."

Instructions doesn't render HTML This whole topic is scoped to Description and Opening — the two fields users actually see. Instructions is read by the model as plain text; the model doesn't "see" markup the way a browser renders it, so HTML there does nothing useful.
the one rule that matters ❤

The HTML toggle — and its cost

There's a per-bot HTML toggle on Description and Opening. Turn it on and your markup renders. It comes with a tradeoff most builders don't find out about until something breaks.

HTML and a JSON world book do not work together Confirmed, repeatedly, across multiple bots: turning HTML on silently stops an attached world book from firing at all — not partial, not bot-specific. Flip HTML back off and the same world book fires again immediately, same session, no re-upload. This is a platform-level either/or, not a bug to route around. If a bot needs its world book to actually work, HTML is off the table for that bot.

Pick one per bot, deliberately, before you build. A world-book-driven bot with a lot of on-demand lore should stay plain text. A bot whose main draw is a strong visual first impression can go HTML and either skip the world book or fold that lore into Instructions instead, where it doesn't need to render — it just needs the model to read it.

What Tipsy's renderer actually supports

The overview, not the recipe book — enough to know what's on the table before you go looking further.

❤ Real typography

Custom web fonts, not just the handful of safe system fonts. If you know how to load a font by URL, that's a real option — pick something that fits the bot instead of defaulting to whatever's easiest.

❤ Collapsible sections

Native browser disclosure elements work with zero JavaScript. Useful for offering deep lore as "expand for more" instead of forcing every reader through the full card before they've even started a chat.

❤ Inline media

Images from an external host render normally. Audio is also possible — a working player with real transport controls — if the file is hosted somewhere that serves it correctly.

❤ Layout & color

Standard CSS — spacing, color, borders, backgrounds. A card can look genuinely designed instead of defaulting to whatever plain text produces.

this is the ceiling, not a tutorial Getting each of these to actually render correctly — which hosts cooperate, what exact markup survives, how to structure it well — took real trial and error to work out. This page tells you what's possible so you know it's worth attempting. The exact implementation is left as an exercise; that's on purpose.
the fine print ❤

Where the walls are

It's real HTML rendered in a real browser, but it's not a blank canvas.

❤ Some markup gets stripped

Tipsy sanitizes what you submit. Scripts don't run — that's a security boundary, not a bug, and it isn't going away. If something you paste behaves differently than it would in a normal browser tab, sanitization is the first thing to suspect.

❤ External resources need to cooperate

Anything loaded from outside Tipsy — fonts, images, audio — depends on that host allowing it: public access, the right content type, permissive cross-origin settings. A private repo or a host that blocks hotlinking fails silently for everyone except you.

❤ It's per-bot, not global

The toggle lives on each bot individually. Flipping it for one bot doesn't touch any other bot's Description or Opening behavior.

a quick note on images ❤

Hosting images the smart way

Tipsy's own image uploader has a small number of slots shared across your entire account — not per bot. It's easy to burn through without realizing until you're stuck.

An external image host doesn't have that ceiling and works the same way HTML expects any external resource to work — a direct, publicly-reachable URL. Use one instead of Tipsy's own uploader for card images.

keep your avatar and your card images separate Whatever image serves as the bot's profile picture doesn't have to be — and usually shouldn't be — reused as a hero or detail image inside the Description/Opening card body. Choose card images for what the card itself needs.
before you flip the toggle ❤

Decide before you build

A few questions worth answering before you commit a bot to HTML mode.

1

Does this bot need a world book to function?

If yes, that answers the question for you — plain text, world book on. HTML isn't worth trading away lore the model actually needs to retrieve.

2

Is the payoff a stronger first impression, or something the model needs to know?

HTML only helps the former. The model never sees the rendered result — it only ever reads Instructions as plain text, so anything mechanically important still belongs there, not in styled markup.

3

Do you have somewhere reliable to host anything external?

Fonts, images, audio — all of it depends on a host that'll actually keep serving the file. Sort that out before you build the card around it, not after.
